## Что реализовано

Этап 1. Каркас unpacked-расширения: TypeScript strict, Vite, Vitest, popup, предпросмотр, настройки, синтетические фикстуры, нормализация занятий. Запись в календарь закрыта.

Этап 2. Чтение открытой страницы `https://stud.ibnd.ru` по кнопке. Разбирается только `table.table-schedule`. Результат показывается в предпросмотре. В календарь ничего не отправляется.

Сделано в данных и правилах:

- Часовой пояс вуза задаётся явно: `Europe/Moscow`. Часовой пояс компьютера не используется. Время хранится как RFC3339 с offset `+03:00`.
- Один вуз: origin `https://stud.ibnd.ru`, `sourceKey` `ibnd:schedule`, `parserVersion` `ibnd-schedule-1`.
- День берётся из заголовка вида `Вт, 13.10.2026` или `Пн, 2.11.2026`. Время — две строки в ячейке. Название, преподаватель и аудитория читаются из своих ячеек.
- Строка `Webinar` и номер аудитории дают тип «вебинар» и номер комнаты. Адрес встречи в снимок не попадает. Если тип на сайте не указан, в занятие ставится «оффлайн». Тип пары в черновик события Google не входит.
- В настройках есть «Название группы». При следующем чтении оно попадает в занятия, у которых сайт сам группу не указал. Пустое название группу не подставляет.
- Стабильного номера занятия на странице нет. `identityConfidence` остаётся `ambiguous`. Две пары одного предмета в один день остаются двумя занятиями. Полностью одинаковые строки блокируются, а не сливаются.
- Если таблица есть, в ней есть хотя бы один верный день и нет заблокированных строк, период помечается полным: от первой даты заголовка до дня после последней. Дни без пар на сайте не показаны; для этого есть предупреждение, а не дырка в покрытии.
- Нет таблицы — это ошибка чтения, а не пустой семестр. Пустая таблица не затирает прошлый снимок. Неудачное чтение тоже не затирает прошлый снимок.
- Пустые настройки на вкладке `stud.ibnd.ru` заполняются этим origin и `Europe/Moscow`. На других сайтах чтение остаётся закрытым, пока пользователь сам не укажет сайт и пояс.
- Кнопки сравнения и подтверждения в интерфейсе неактивны. `googleCalendarWrite()` бросает ошибку.

Проверено по сохранённой странице семестра, файл лежит вне репозитория: таблица читается, в результате нет адресов `http` и `mts-link`, покрытие 2026-10-13 … 2026-12-20 исключительно, статус полный, занятий больше 50. ## Известные ошибки и ограничения

- `src/content/reader.ts` по-прежнему отвечает, что реальный адаптер не настроен. Рабочий путь чтения идёт через `extractIbndSchedule`.
- У строк нет устойчивого id. Перенос выглядит как исчезновение в одном месте и новая пара в другом. Автоматически обновить то же событие нельзя, и этого обещать нельзя.
- Отменённая пара пропадает из таблицы. Удаление события календаря не предлагается.
- Полнота семестра принята потому, что страница показывает весь семестр и в проверенном файле нет заблокированных строк. Дни без пар в таблице отсутствуют. Если на экране окажется не вся таблица, снимок всё равно может быть помечен полным.
- Тест сохранённого файла привязан к пути вне репозитория. В git этот HTML не входит.
- Живое чтение в Chrome пользователя этой записью не подтверждено.
- Старую карточку расширения нужно удалить и загрузить каталог `dist` заново. Пока на карточке старый ID, Google этот вход отклонит: клиент уже ждёт `fgaajikioedkgeddlpfolngopnpkjegm`. Локальные настройки при смене карточки не переносятся. Календарь в Google остаётся, его можно найти кнопкой «Найти календарь расширения».

## Принятые решения

- Селекторы взяты из сохранённой разметки таблицы, не из подписей на снимке экрана инструментов разработки.
- Ссылки встреч не хранятся и не используются как идентификатор: одна ссылка повторяется у разных занятий.
- Фамилии и сохранённая страница в репозиторий не копируются. В фикстуре стоят заглушки.
- Для этого одного сайта пустые настройки заполняются сами. Для остальных сайтов пустые настройки чтение блокируют.
- Неудачное чтение не выглядит как массовая отмена: прошлый снимок остаётся.
- Предпросмотр после чтения открывает popup один раз. Service worker вторую вкладку не открывает.
- Функция, которую Chrome выполняет на странице, содержит весь разбор внутри себя. Иначе сборщик мог бы оставить помощников в модуле расширения, и на странице их не было бы.
- Области Google — `calendar.app.created` и `calendar.calendarlist` для цвета этого календаря. Полный доступ ко всем календарям не запрашивался.
- Календарь только с тем же названием сам не выбирается. Если номер забыт и календарь с парами расширения ровно один, запись подхватывает его. Идентификатор события резервируется до запроса и при повторе не меняется.
- Тип пары в событие не входит.
- Доступ одногруппникам — только список Test users. Пароль, код дня и код владельца в расширение не добавляются. Приватный `.pem` в репозиторий не кладётся. В manifest лежит только публичный ключ уже созданной упаковки.
- Новая копия для друзей собирается командой `npm run share` в `release/raspisanie-vuza.zip`. Если заполнен `update.public.json`, та же команда публикует выпуск GitHub. Расширение с 0.8.3 показывает «Доступна новая версия» и кнопку «Скачать». Папку Chrome сам не подменяет: друг распаковывает архив и нажимает «Обновить» в Chrome.
