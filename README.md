# Расписание вуза

Локальное расширение Chrome (Manifest V3), версия 0.8.3. Оно читает таблицу расписания на уже открытой вкладке `https://stud.ibnd.ru` и записывает пары в отдельный календарь Google «Расписание вуза». Пароль кабинета в расширение не вводится. Автоматическая проверка по таймеру в эту версию не входит.

Описание для владельца — [docs/owner.md](docs/owner.md). Техническое задание — [docs/spec.md](docs/spec.md). Версии 0.6–0.9 — [docs/roadmap.md](docs/roadmap.md). Текущее состояние — [docs/status.md](docs/status.md).

## Что делает расширение

- Читает только `table.table-schedule`. Часовой пояс вуза — `Europe/Moscow`.
- Одна пара — одно событие без повтора и без гостей. Ссылка вебинара в событие не попадает.
- «Сравнить все пары», затем «Записать изменения»: создаёт недостающие пары и обновляет изменившиеся. Повтор того же снимка новых событий не создаёт.
- Пара, которую поправили вручную в Google, не перезаписывается, если на сайте она не менялась.
- «Подтвердить отмены» удаляет только пары, которых нет в полном снимке. Неполный снимок отмены не предлагает. Чужие события не удаляются.
- Перенос без постоянного номера занятия — это новая пара. Старая удаляется только кнопкой отмен.
- В настройках три темы: светлая, тёмная и тёмная рваная. Рваная использует цвета тёмной темы и на больших страницах показывает рваные карточки. Маленькое окно остаётся ровным.
- Цвет календаря задаётся в настройках одним запросом. «Удалить календарь» удаляет только календарь, который создало расширение. «Очистить локальные данные» номер этого календаря сохраняет. Если номер уже забыт, «Найти календарь расширения» показывает подходящие календари, и удаляется только выбранный.
- Доступ одногруппника включается в Google, в списке Test users, а не кнопкой расширения. Пароль, код дня и код владельца в расширение не входят.

## Проверка сборки

Нужен Node.js 20 или новее.

```powershell
npm install
npm test
npm run typecheck
npm run build
```

`npm test` запускает Vitest. `npm run typecheck` проверяет TypeScript. `npm run build` повторяет проверку типов и собирает каталог `dist`.

## Установка в Chrome

1. Откройте `chrome://extensions`.
2. Включите режим разработчика.
3. Нажмите «Загрузить распакованное расширение» и выберите каталог `dist` этого проекта, не корень репозитория.
4. После изменений в коде снова выполните `npm run build` и нажмите обновление на карточке расширения.

ID расширения зафиксирован публичным ключом в manifest. Копия каталога `dist` на другом компьютере получает тот же ID. Приватный `.pem` в копию не входит. Если удалить старое расширение и загрузить `dist` заново, на карточке должен быть ID `fgaajikioedkgeddlpfolngopnpkjegm`. Обычное обновление карточки этот ID не подхватит: Chrome считает его другим расширением.

## Google

Области доступа две. `https://www.googleapis.com/auth/calendar.app.created` создаёт календарь приложения и события в нём. `https://www.googleapis.com/auth/calendar.calendarlist` нужна только для цвета этого календаря. Client secret в расширение не входит. Токен в настройки не записывается.

Пока нет файла `oauth.public.json`, кнопки Google ничего не запрашивают.

В консоли Google названия разделов такие: **Google Auth platform** и внутри него **Branding**, **Audience**, **Clients**. Calendar API включается в **APIs & Services**, раздел **Library**.

1. Создайте проект и включите Google Calendar API.
2. В **Branding** укажите название приложения. Это название видит человек на экране согласия.
3. В **Audience** оставьте режим Testing и добавьте свой Google-аккаунт в Test users. В этом режиме доступ есть только у этих пользователей, не больше 100. Токен testing-приложения живёт около 7 дней: потом нужно снова нажать «Подключить Google». Приложение не публикуйте и оплату Google Cloud не включайте.
4. В **Clients** нажмите Create client, тип Chrome Extension. В Item ID вставьте ID расширения со страницы `chrome://extensions`. Это 32 символа.
5. Скопируйте `oauth.public.example.json` в `oauth.public.json` и вставьте client ID. Это публичный идентификатор, не пароль.
6. Выполните `npm run build` и обновите расширение.
7. В настройках расширения нажмите «Подключить Google» и подтвердите доступ. Цвет сохраняется кнопкой «Сохранить».

Разрешение отзывается в аккаунте Google. «Очистить локальные данные» сам календарь и разрешение не трогает, но сохраняет его номер, чтобы удаление оставалось доступным.

## Одногруппники

Пароль, ежедневный код и постоянный код владельца в расширение не входят. Пока приложение в режиме Testing, замок — список Test users. Приложение в Production не переводите, проверку Google не запускайте, оплату не включайте и новые области доступа не добавляйте.

Добавить почту: Google Auth platform → Audience → Test users. Впишите Gmail одногруппника. В списке не больше 100 почт. Токен режима Testing живёт около 7 дней: потом человеку нужно снова нажать «Подключить Google».

Что видит одногруппник:

- свой Google-аккаунт и свой календарь «Расписание вуза». Календарь владельца и его пары ему не отдаются. Токен владельца в хранилище расширения не передаётся;
- чтение только открытой вкладки `https://stud.ibnd.ru`, после своего входа в кабинет;
- пока его почты нет в Test users, Google отвечает `access_denied`, даже если у него есть копия расширения.

Убрать человека: удалите почту из Test users. Расширение на его компьютере остаётся. Календарь и уже записанные пары в его Google остаются. Следующий вход или обновление токена Google отклоняет.

Как отдать копию:

1. Один раз создайте публичный репозиторий GitHub. Скопируйте `update.public.example.json` в `update.public.json` и впишите `owner/name` в поле `repository`. Установите GitHub CLI и выполните `gh auth login`. Этот файл в git не входит.
2. Выполните `npm run share`.
3. Команда собирает `dist`, записывает `release/raspisanie-vuza.zip` и, если репозиторий указан, публикует выпуск с этим архивом. Пока репозиторий не указан, архив остаётся только на диске: отправьте его вручную.
4. `oauth.public.json` в архив не входит. Публичный client ID уже записан в `dist/manifest.json` при сборке. В переписку и в документы client ID не копируйте. Приватный `.pem` и `dist.crx` в архив не входят.

Первая установка: одногруппник распаковывает архив и загружает внутреннюю папку `dist` как распакованное расширение. Копия 0.8.2 сама новую версию не замечает: один раз её нужно заменить на 0.8.3 вручную.

Новая версия:

1. После `npm run share` у того, у кого уже стоит 0.8.3 или новее, при открытии расширения появляется «Доступна новая версия» и кнопка «Скачать». Кнопка открывает архив этого выпуска на GitHub.
2. Распакуйте архив поверх той же папки `dist`, которую Chrome уже загрузил.
3. На `chrome://extensions` нажмите «Обновить» на существующей карточке.
4. Вторую копию не загружайте. Календарь и настройки остаются, потому что ID тот же: `fgaajikioedkgeddlpfolngopnpkjegm`. Расширение само папку не подменяет.

В manifest записан публичный ключ, поэтому у копии `dist` на любом компьютере ID `fgaajikioedkgeddlpfolngopnpkjegm`. Этот же ID указан в клиенте Google. Приватный `dist.pem` в архив и в репозиторий не кладётся. Файл `dist.crx` одногруппнику не нужен: он загружает распакованный каталог `dist`.

## Ручная приёмка

Календарь, который уже записан, для этого списка удалять не нужно.

1. Удалите старую карточку расширения и заново загрузите каталог `dist`. На карточке должны быть версия 0.8.3 и ID `fgaajikioedkgeddlpfolngopnpkjegm`. Обычная кнопка обновления старый ID не меняет. Пока нет более нового выпуска на GitHub, строка «Доступна новая версия» не показывается.
2. Откройте страницу расписания на `stud.ibnd.ru`, уже войдя в кабинет. Нажмите значок расширения и «Считать расписание». Должны появиться число занятий и предпросмотр. Само чтение в календарь ничего не пишет.
3. На предпросмотре проверьте дату, время `+03:00` и аудиторию. У вебинара не должно быть адреса встречи.
4. Нажмите «Сравнить все пары», затем «Записать изменения». Повторное сравнение того же снимка не должно создавать новые пары.
5. Если какая-то пара пропала из полного снимка, «Подтвердить отмены» удаляет только её и перед этим спрашивает подтверждение. «Записать изменения» эту пару не удаляет.
6. В настройках смена цвета обновляет цвет календаря одним запросом. «Удалить календарь» спрашивает подтверждение и удаляет только «Расписание вуза». После очистки локальных данных эта кнопка остаётся рабочей. Если номер уже был забыт раньше, «Найти календарь расширения» просит выбрать календарь и без выбора ничего не удаляет.
7. В настройках есть раздел «Доступ одногруппникам»: доступ включается в Test users, не кнопкой расширения. Поля пароля там нет.

«Открыть предпросмотр» без чтения показывает тестовые наборы. В обычной неделе пять занятий, у «Баз данных» текст «Аудитория не указана». Для страниц без установки можно запустить `npm run dev` и открыть `src/ui/review/index.html`. Там данные лежат в `localStorage` и не являются хранилищем Chrome.

## Ограничения

Запись и отмена идут только после сравнения и отдельного подтверждения. Неполный снимок и ошибка чтения отмены не запускают. Таймер в эту версию не входит. Полные правила — в [docs/spec.md](docs/spec.md). Известные ограничения текущей сборки — в [docs/status.md](docs/status.md).
