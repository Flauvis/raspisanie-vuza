# Техническое задание: University Calendar Sync

Правила для агента — в [AGENTS.md](../AGENTS.md). Версии после 0.5.0 — в [roadmap.md](roadmap.md). Установка и раздача копии — в [README.md](../README.md).

## 1. Цель и MVP

Chrome desktop extension, Manifest V3. Локальное чтение DOM открытой пользователем страницы расписания → нормализация → предпросмотр → сравнение с Google Calendar → подтверждённые изменения.

Одна пара = одно обычное событие; recurring events в MVP не использовать. Один вуз/профиль и один календарь, созданный приложением. Односторонняя синхронизация. Автоматизация входа в вуз, сервер, мобильное приложение, публикация в магазине и фоновое чтение закрытых страниц вне scope.

## 2. Стек и структура

Стек: TypeScript strict, Vite с поддержкой сборки MV3, простые HTML/CSS интерфейсы без React, Vitest. Результат загружается как unpacked extension.

Пример структуры:

- src/background/ — service worker, OAuth, Google API, координация операций.
- src/content/ — извлечение расписания; никаких Google-токенов.
- src/adapters/ — UniversityAdapter, mock и реальный адаптер.
- src/domain/ — модели, валидация, нормализация, сопоставление, diff.
- src/calendar/ — API-клиент и преобразование занятия в Google event.
- src/storage/ — настройки, mapping, журнал незавершённых операций.
- src/ui/popup/ — запуск чтения и открытие интерфейса.
- src/ui/review/ — список занятий, ошибки, план изменений, подтверждение.
- src/ui/options/ — настройки, подключение Google, очистка данных.
- tests/fixtures/ — только синтетические и обезличенные примеры.
- README.md, manifest, package scripts.

Бизнес-логика не должна зависеть от chrome API или DOM. Все внешние взаимодействия через интерфейсы для тестирования.

Сложившаяся карта, перенесённая из статуса. Ранние формулировки вроде «запись закрыта» относятся к этапу до подтверждённой синхронизации; живой путь записи — `src/calendar/sync.ts`.

Домен, без Chrome и без DOM страницы вуза:

- `src/domain/types.ts` — занятия, снимок, настройки, статусы.
- `src/domain/time.ts` — гражданские даты, IANA-пояс, RFC3339, отказ на пропуске и наложении летнего времени.
- `src/domain/normalize.ts` — проверка строк, предупреждения, хеш снимка, тип «оффлайн» по умолчанию и подстановка названия группы. Хеш не включает время захвата.
- `src/domain/canonical.ts` — каноническая строка с фиксированным порядком ключей.
- `src/domain/settings.ts` — проверка origin, префикса пути, пояса и названия группы.
- `src/domain/read-gate.ts` — можно ли читать активную вкладку.
- `src/domain/cancellation.ts` — отмена допустима только при полном снимке, том же источнике, доказанной принадлежности и отдельном подтверждении.
- `src/domain/status.ts` — подписи статусов. Время последней проверки и время последней успешной записи разделены.
- `src/domain/log.ts` — в журнал пишутся код, счётчик и технический идентификатор операции.

Адаптеры:

- `src/adapters/ibnd/extract.ts` — самодостаточная функция чтения таблицы. Её можно передать в `chrome.scripting.executeScript`. Рядом очистка результата: длина, число записей, запрет строк с `://`.
- `src/adapters/ibnd/adapter.ts` — origin и сборка снимка из уже извлечённых записей.
- `src/adapters/live.ts` — живой адаптер включён только для origin вуза.
- `src/adapters/real/adapter.ts` — точка входа живого адаптера. Без документа таблицы возвращает отсутствие таблицы.
- `src/adapters/mock/` и `src/adapters/fixture.ts` — синтетические наборы предпросмотра.
- `src/content/reader.ts` — старый закрытый читатель. Живой путь его не вызывает.

Фон, хранение, календарь:

- `src/background/service-worker.ts` — сообщения, инъекция функции чтения в активную вкладку, локальное хранилище с доступом `TRUSTED_CONTEXTS`.
- `src/background/handle-message.ts` — проверка отправителя, чтение, сохранение снимка, подтверждённая запись и отмена.
- `src/background/google-auth.ts` — единственное место с `getAuthToken`. Интерактивный вход только по кнопке.
- `src/storage/state.ts` и `src/storage/browser-store.ts` — состояние расширения. В режиме страницы без Chrome используется `localStorage`.
- `src/calendar/writes.ts` — общая запись выключена и бросает ошибку. Черновик события не содержит тип пары.
- `src/calendar/sync.ts` — план и подтверждённая запись всех пар снимка.
- `src/calendar/colors.ts` — палитра цвета календаря.
- `src/calendar/recover.ts` — какие календари можно показать при потере номера.
- `src/calendar/google-http.ts` — адрес Google API, публичная проверка client ID, один повтор при 401 и ограниченный повтор при 429/5xx.
- `src/calendar/google-api.ts` — список календарей, создание календаря и события. Токен остаётся в заголовке запроса и в состояние не пишется.
- `src/calendar/test-write.ts` — план одной самой ранней пары и подтверждённая запись. Чужой календарь по названию не забирается.
- `oauth.public.example.json` — пустой образец client ID. Настоящий файл `oauth.public.json` в git не входит.

Интерфейс, русский:

- `src/update/check.ts` — сравнение номера версии с последним выпуском GitHub. Ссылка принимается только на выпуски указанного репозитория. Без `update.public.json` проверка выключена.
- `src/ui/shared/update-notice.ts` — строка «Доступна новая версия» и кнопка «Скачать» в маленьком окне, настройках и предпросмотре.
- `src/ui/popup/` — кнопка «Считать расписание». После успешного чтения открывает предпросмотр.
- `src/ui/review/` — таблица занятий и тестовые наборы. Последнее чтение с сайта показывается отдельно.
- `src/ui/options/` — пояс, подпись профиля, origin и префикс пути, темы, очистка локальных данных. Раздел «Доступ одногруппникам» объясняет, что почта добавляется в Test users, а не кнопкой расширения.
- `src/ui/shared/dom.ts` — текст выводится через `textContent`, не через `innerHTML`.
- `src/ui/shared/theme.ts` — сохранённая тема до отрисовки страницы.

Сборка:

- `vite.config.ts` — цель Chrome 120, относительные пути, из HTML убирается `crossorigin`. Поле `key` содержит только публичный ключ. `oauth2` и host permission на Google появляются только если в сборке есть корректный client ID.
- `tests/fixtures/` — обезличенные JSON и `ibnd-week.html`. В фикстуре преподаватель записан как «Преподаватель 1», ссылка вебинара — на `example.invalid`.
- `.gitignore` — `oauth.public.json`, `*.pem`, `*.crx` и каталог `release/` с архивом для одногруппников не входят в git.

## 3. Разрешения и безопасность

Базовые permissions: activeTab, scripting, storage, identity. Для Google API — минимальный host permission на https://www.googleapis.com/* при необходимости выбранного клиента. Если в сборке указан репозиторий обновлений, добавляется чтение только `https://api.github.com/repos/<owner>/<name>/*`. Это не новая область OAuth.

Чтение DOM запускается по пользовательскому действию через activeTab + scripting; не внедрять content script на все сайты. Перед инъекцией проверить настроенный origin и допустимый путь. До настройки сайта чтение заблокировано с понятным сообщением. Не требовать cookies, webRequest, history, <all_urls> и доступ к login-страницам.

OAuth: chrome.identity.getAuthToken в background с interactive:true только по явному нажатию. Остальные запросы — non-interactive. Области: https://www.googleapis.com/auth/calendar.app.created для календаря приложения и событий в нём; https://www.googleapis.com/auth/calendar.calendarlist только для цвета этого календаря. Не расширять scope молча. OAuth client ID — публичный идентификатор, не секрет. Не включать client secret в расширение.

Запрет: пароли, токены кабинета, чтение cookies, удалённый исполняемый код, eval, HTML через innerHTML из недоверенных данных, отправка страницы на сервер или модели. Все зависимости упаковываются локально.

Google access tokens не хранить в storage.local/sync и не отправлять content script. Использовать кэш identity API; временные значения только в памяти или session при обосновании. Ограничить доступ storage.local до TRUSTED_CONTEXTS, если API поддерживается целевой версией Chrome. Валидировать runtime messages, sender и схему payload. Content script не может инициировать произвольную запись в Google.

Логи: коды ошибок, счётчики, технические operation IDs. Без токенов, HTML, ФИО и полного расписания. Предусмотреть очистку локальных данных и отдельно объяснить отзыв OAuth в Google.

В служебные поля события не класть персональные URL и секреты. Не использовать sendUpdates=all: без приглашений и без гостей. Не обходить вход, MFA и CAPTCHA. Не читать скрытые страницы без отдельной спецификации. Ошибка чтения, выход из кабинета, пустая незагруженная страница и неполный снимок не приводят к массовой отмене.

## 4. Контракт данных

Lesson:

- sourceLessonId?: string — стабильный ID исходного занятия, если существует;
- localIdentity: string — внутренний устойчивый ID после сопоставления;
- title: string;
- start/end: RFC3339 timestamps с явным offset;
- timeZone: IANA string, обязательный, не выводить из timezone компьютера;
- room?: string;
- teacher?, group?, lessonType?, building?: string;
- sourceDate: YYYY-MM-DD;
- identityConfidence: stable | confirmed | ambiguous.

ScheduleSnapshot:

- sourceKey: string — namespace вуза и профиля, без секрета и полного личного URL;
- capturedAt;
- coverage: { startDate, endDateExclusive, timeZone };
- coverageStatus: complete | partial | unknown;
- lessons: Lesson[];
- warnings: structured messages;
- parserVersion;
- snapshotHash.

UniversityAdapter:

- canHandle(url);
- extract(document) → raw records + metadata;
- normalize(raw, settings) → ScheduleSnapshot.

Отличать ошибку, неполную страницу и корректное пустое расписание. coverageStatus=complete только при проверяемых признаках полной загрузки нужного периода, включая пустые дни. Для неизвестной разметки fail closed.

## 5. Разбор расписания

Извлекать только нужный блок DOM. SPA/loading, iframe, virtualized list, pagination и lazy loading не считать автоматически решёнными: обнаруживать ограничение и сообщать. Не обходить скрытые страницы без отдельной спецификации.

Даты, год, числитель/знаменатель и номера недель нельзя угадывать. Если сайт даёт номер пары, требовать подтверждённую таблицу звонков. start < end. Все обязательные поля валидируются. Если аудитория отсутствует — warning и текст «Аудитория не указана», не выдумывать номер. Если отсутствует время или дисциплина — запись блокируется.

Для local date/time + IANA timezone использовать библиотеку с корректной обработкой DST либо Temporal с polyfill. Не применять new Date к неоднозначным локальным строкам. Несуществующие и двусмысленные времена требуют явной обработки. Ошибки в части строк делают snapshot partial; валидные строки можно добавлять и обновлять после просмотра, но отмены запрещены.

## 6. Google Calendar

Календарь создаётся только после явного согласия; хранить его ID. Название «Расписание вуза» не использовать как единственный идентификатор. При потере ID не присваивать себе произвольный календарь с таким же названием; показывать восстановление и выбор подтверждённого календаря приложения. Если календарь с парами этого расширения ровно один, подтверждённая запись может подхватить его. Если таких календарей несколько, новый не создаётся.

Event:

- summary = title;
- start/end = { dateTime, timeZone };
- location = аудитория или корпус при наличии;
- description = «Аудитория: ...» + доступные teacher/group/type;
- extendedProperties.private = { app: "university-calendar-sync", schemaVersion: "1", sourceKey, lessonKey: localIdentity, sourceHash }.

Служебные свойства — строки. Не включать персональные URL и секреты. Создавать events.insert, менять только управляемые поля через events.patch, удалять только подтверждённые события через events.delete. Не использовать sendUpdates=all: никаких приглашений и attendees в MVP.

Читать все страницы events.list; фильтровать собственные события через privateExtendedProperty и перепроверять ownership. Получать известные mapping IDs отдельно, чтобы найти события, вручную перенесённые за текущий диапазон. При отменах исходный период сверять с последним source snapshot, а не только текущим временем события в Google. Пара вне прочитанного периода удаляется только если расширение само её раньше записало.

## 7. Идентичность и diff

Стабильный sourceLessonId предпочтителен. Изменяемые title/start/room не должны быть единственной идентичностью.

Без стабильного ID:

1. Точное совпадение неизменившихся записей.
2. Однозначное сопоставление по доступным признакам внутри согласованного периода.
3. Неоднозначные кандидаты → needsReview; показать старую и новую пару и дать вручную подтвердить связь.
4. После подтверждения сохранить localIdentity и mapping.

Нельзя обещать гарантированное автоматическое распознавание переноса без устойчивого ID. Две одинаковые по предмету пары в один день должны оставаться двумя событиями. Если источник содержит полностью неразличимые записи, блокировать неоднозначную часть, а не объединять её молча.

Diff: create, update, unchanged, cancellationCandidate, conflict, invalid. Хеш управляемых полей вычислять из канонической нормализованной записи с фиксированным порядком ключей, не из случайного JSON или HTML.

Сравнивать не только локальный cache, но и текущее состояние Google. Если пользователь менял управляемые поля события вручную — conflict и выбор «применить вуз / пропустить». Не затрагивать личные reminders, color и прочие неуправляемые поля. Нет двухсторонней синхронизации.

Удаление по умолчанию не входит в «Записать изменения». cancellationCandidate допустим только при complete snapshot, совпадающем sourceKey, доказанном полном coverage и принадлежности события проекту. Перед удалением отдельное подтверждение. Ошибка чтения, logout, пустая незагруженная страница или partial snapshot никогда не приводят к массовой отмене.

## 8. Выполнение и устойчивость

Никаких записей до подтверждения. План содержит конкретные targets и связан со snapshotHash. Если данные изменились после предпросмотра, заново построить и подтвердить план. Защититься от повторного клика и параллельных sync.

Service worker MV3 не считать постоянно живущим. Сохранять journal: operation ID, состояние, lessonKey, target event ID и approved payload. Не сохранять токены. Mapping фиксировать после подтверждённого успешного ответа, а не до запроса.

Создание должно выдерживать потерю ответа и повторный запуск: резервировать допустимый клиентский Google event ID, созданный из UUID в разрешённом формате, сохранять его до запроса. При conflict или неизвестном результате читать событие по ID и проверять метаданные. Слепой повтор insert с новым ID запрещён.

Для update и delete проверять актуальную версию или etag и использовать условные запросы, если поддерживаются; при внешнем изменении показывать conflict, не перезаписывать молча. Не обещать атомарность группы запросов. Частичный успех отображать отдельно; повторять только невыполненные операции. Продолжение прерванного плана — после проверки Google и нового подтверждения оставшихся действий.

401: удалить невалидный cached token, повторить получение non-interactive один раз, затем запросить ручное подключение. 403 не считать автоматически истечением токена: отдельно различать scope, quota и доступ. 429, временные rate-limit 403 и 5xx: bounded exponential backoff с jitter и Retry-After, без бесконечных циклов. Нет сети — сохранять статус, не удалять события и не применять автоматически позже без актуального просмотра.

## 9. UI

Русский интерфейс. Popup: статус конфигурации, подключение Google, «Считать расписание», открыть обзор. Review page: период и полнота, таблица title/date/start/end/room, предупреждения, old → new, выбор операций, dry-run и подтверждение. Options: timezone, профиль источника, календарь, очистка локальных данных, инструкции.

Статусы: not configured, ready, reading, review required, syncing, partial success, success, source unavailable, auth required, error. Не показывать «синхронизировано», если были пропуски или ошибки. Последняя проверка и последняя успешная запись — разные timestamps.

## 10. Этапы реализации

1. Каркас, сборка, mock fixtures, UI и unit tests. Никакого Google write.
2. Реальный DOM-адаптер после получения обезличенных примеров. Read-only preview.
3. Google OAuth, read/dry-run, подтверждённое создание календаря и одной тестовой пары.
4. Diff, mapping, idempotency, updates, conflicts, журнал.
5. Отдельно подтверждаемые отмены и recovery tests.
6. README и ручная приёмка. Автоматический режим не добавлять в MVP.

Этапы 1–6 сделаны. После каждого нового этапа: что сделано, команды проверки, результаты тестов, ограничения, какой input нужен дальше. Не заявлять реальные OAuth и проверки на сайте вуза, если не было доступа к среде пользователя.

## 11. Тесты и приёмка

Unit и fixture tests:

- обычная неделя, пустой полный период, partial, loading, logout;
- отсутствующая аудитория, неправильное время, неоднозначный год;
- timezone компьютера отличается от timezone вуза, DST;
- повторная синхронизация → 0 новых;
- смена аудитории → update того же event ID;
- перенос со stable ID → update;
- перенос без stable ID → review при неоднозначности;
- две пары одного предмета в день → не объединять;
- partial snapshot → 0 deletion candidates;
- чужие события и другой sourceKey → нет изменений;
- manual Google edit → conflict;
- потеря insert response и повтор → один event;
- pagination, 401, quota, 429, 5xx, restart worker;
- входные строки с HTML → безопасное отображение.

README хранит установку Node и зависимостей, команды dev, test, build и typecheck, загрузку dist в chrome://extensions, настройку Google Cloud и Calendar API, consent screen и test users, OAuth client для расширения с привязкой к стабильному extension ID, client ID, ограничения testing mode и permissions. Названия разделов консоли сверять по актуальной документации. Не обещать, что смена extension ID сама сохранит OAuth.

## 12. Будущий автоматический режим

Только отдельным этапом: расписание проверок через chrome.alarms, optional host permissions для конкретного вуза, чтение доступной авторизованной страницы. Не обходить login, MFA и CAPTCHA. Закрытый браузер означает отсутствие проверок. Закрытая нужная страница означает, что чтение DOM недоступно, пока не согласована другая архитектура. Автоматические удаления остаются выключенными. В версии 0.6–0.9 этот режим не входит.
